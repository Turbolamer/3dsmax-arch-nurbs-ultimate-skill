## 2. Геометрический контракт S1 → S4w

### 2.1 Поэтажный footprint и толщина

`walls.json` остаётся доменной спецификацией; изменение версии схемы и точные имена новых
полей утверждаются в фазе 1. Обязательная семантика:

- project/storey/contour/segment ID и связь с источником размеров;
- простой замкнутый плоский полигон, нормализованный **CCW**, с явными base/top отметками;
- `inner`/`outer` reference исходного контура, положительная толщина и её provenance;
  отсутствующий размер — явно журналируемое допущение, не скрытый default builder;
- канонические cm, transform/local origin и units guard для нативной сцены;
- стабильное соответствие ID исходных сегментов нормализованному порядку, в том числе
  после исправления winding. Повтор первой точки не создаёт нулевой сегмент.

Начальный production-поднабор: прямые сегменты, простая оболочка без дыр в footprint,
постоянная толщина на одну оболочку этажа. Разные этажи могут иметь разные footprints
и высоты. Кривые, переменная толщина, пересекающиеся объёмы или сложное объединение этажей
не считаются поддержанными без отдельного контракта; неподдерживаемость объявляется до записи.
Проёмы первой версии — прямоугольные в локальных `(s,z)`, не пересекаются и не заходят в углы.
Дверь от пола меняет нижнюю границу поверхности, окно создаёт внутренний граничный цикл.

### 2.2 Offset — проверяемая операция, не обещание Shell

Для CCW-сегмента с tangent `T=(dx/L,dy/L,0)` наружная нормаль
`N=(T.y,-T.x,0)`. Если исходные размеры наружные, сначала строится внутренний
offset; затем наружная оболочка обязана восстановить исходный reference в допуске.
Знак расстояния и направление фиксируются данными и независимой проверкой.

До создания Max-геометрии проверяются finite/planarity/closure, ненулевые длины и площадь,
дубли, самопересечения, коллапс inset, изменение допустимой топологии, узкие выемки,
перекрытия нелокальных сегментов и предел miter. После — ещё и фактический evaluated mesh.
Произвольный `straightenCorners=true` не устраняет эти риски.
Нельзя молча обрезать острый угол, менять размеры/толщину или переключать маршрут.
Простой `offset()` из эксперимента **не переносится как production offsetter без валидации**.

### 2.3 Единый периметр этажа

1. Сохранить закрытый направляющий `SplineShape` как проектный объект, не терять источник:
   **это требование пользователя**, даже если mesh вычисляется без зависимости от spline.
2. Собрать станции `s` из границ сегментов и проёмов. Для Z использовать **whole-floor union**:
   base/top + все sill/head этого этажа, отсортированные с согласованным numeric epsilon.
3. Построить один `Editable_Poly` периметра. Соседние фасады используют одни vertex ID
   на каждом общем углу и уровне Z; совпадение координат без общей топологии недостаточно.
4. Удалить именно грани проёмов и ненужные isolated vertices. Проверить поверхность до толщины.
5. Добавить ровно один `Shell`: `innerAmount=0`, `outerAmount=t_native`,
   `straightenCorners=true`, `segments=1`, объявленные smoothing/enabled states. Снять и проверить результат.

Пер-фасадные независимые Z-сетки без stitching запрещены: они возвращают швы/T-junction.
Уменьшение сетки — отдельная измеренная оптимизация после базовой production-приёмки.
Никаких отдельных shell-стен с наложенными углами, глобального Slice или Boolean для проёмов.
Старые operational caps 32 active base faces/256 triangles не подходят: U-проба уже имеет
75/400. В v2 нужны отдельные явные ограниченные бюджеты vertices/faces/triangles/openings,
расчёт стоимости whole-floor union и калибровка коротких batch-вызовов; не снимать лимиты
и не запускать большой случай вслепую. Превышение лимита выявлять до изменения сцены.

### 2.4 Масштаб и численная точность

Переиспользовать `scripts/scene_units.py` и действующий контракт SystemType/SystemScale.
См→native коэффициент применяется один раз к длинам, квадрат/куб — к площади/объёму;
измерения обратно нормализуются. Единицы сцены не менять.
Геометрический допуск, numeric epsilon и точность сериализации — разные параметры.
Float32 при больших координатах требует бюджета ошибки/локального origin, не заявления «точно 0».

## 3. Opening manifest и S5 без стеновых ячеек

Манифест S4w является геометрическим интерфейсом S5/QA, а не новым источником исходных размеров.
Он должен содержать:

| Группа | Содержание |
|---|---|
| Идентичность | schema/route version, project/storey/contour/segment/opening ID, source refs, node ownership |
| Геометрия проёма | origin, локальная СК и transform, tangent/outward/up, s-range, sill/head, rough width/height, wall thickness |
| Монтаж | mount reference, подписанный recess относительно этой опоры, frame depth, clearance по сторонам и допустимый overlap |
| Связи | component/prototype ref, placement ID, ожидаемые поверхности контакта, допуски и запись допущений |

Семантика локальных осей и handedness явно документируется; compass label фасада не заменяет
tangent сегмента. Номер полигона Max не является устойчивым opening ID.
Frame depth и recess не выводятся молча из wall thickness; размеры рамы не приравниваются
rough opening без clearance/overlap контракта.

**Цель S5:** существующий instance-placement переиспользуется для заполнений и декора по
манифесту. Для v2 нет `wall_cells`, повторных opening cuts, подмены стены box-пирсами или
отказа лишь по селектору v2. При отсутствии/несовпадении манифеста — ясная ошибка входов,
не legacy fallback. Общая геометрия прототипов проверяется с plain-copy negative control.

**Цель S2:** плиты/крыша/конструктив сохраняются, сплошные дублирующие наружные wall-host
в v2 не создаются. При миграции старые узлы разбираются по доказанному проектному владению;
просто скрыть неизвестный Box недостаточно для приёмки или безопасной миграции.
Legacy Mechanism A остаётся в legacy-ветке и проверяется её QA.

## 4. Простой runtime и поэтапный source cleanup

Нужная безопасность: согласованный оператор, проверенные входы/units/ownership, отсутствие
чужих изменений, точная уборка своих временных узлов и понятная ошибка. Не переносить
в v2 lease, witnesses, nonces, `POISONED`, сравнение всей rootScene, closure layer-manager
и controller/subAnim graph как условие обычной сборки стены.
Действующий v1 runtime требует пустую сцену/единственный слой/единственный узел: это
**production-блокер**, а не полезная проверка для S4w после S2/S3. Его следует заменить
проектной admission/rebuild-проверкой, совместимой с уже существующими плитами/NURBS.

Обычная пересборка:

1. Прочитать текущую сцену и manifest проекта, разрешить конкретные node refs/идентичность.
   Name/prefix/один старый handle сами по себе владение не доказывают.
2. Обнаружить коллизии имён, неизвестные остатки и ручные изменения; не уничтожать их молча.
3. До удаления собрать конкретный список доказанно своих узлов. Пересоздать только разрешённую
   проектную популяцию; получить новый manifest. При ошибке убрать лишь точно созданное этой попыткой.
4. Сравнить семантическую геометрию/ID/количество по трём сборкам. Новые node handles допустимы;
   это **не** обязательный read-only NOOP и не проверка неизменности всей сцены.
5. Доказать, что чужой sentinel и связанные с ним данные не изменены; sentinel с похожим
   префиксом должен также сохраниться. Не требовать `objects.count==0` в общей сцене.

Не заявлять crash-atomic rollback или полное восстановление undo/dirty без доказательств.
Не чистить старые глобальные registry-объекты или сомнительные узлы автоматически.

Очередь source cleanup: выделить v2-путь → заменить старые runtime-тесты тестами геометрии,
ownership и ошибок → удалить неиспользуемые arm/lease/controller-ветви из активного пути →
убрать устаревшие active-doc маршруты. Существующий v1 compatibility-код не удаляется,
пока есть объявленный потребитель. `Audit/` не удаляется wholesale; старые evidence остаются
историей, а не частью runtime. Проверки не связанных со стенами систем сохраняются.

## 5. Независимый профиль S7

Существующий `qa_check.py` — точка расширения, не уже готовая проверка v2.
Ограничения старого wall-профиля (`Y=0`, bbox в `−Y`, wire с абсолютным объёмом)
нельзя наследовать как универсальный сертификат. Нужны сырые signed measurements,
локальные системы каждого сегмента и независимые ожидания из исходной спецификации.
Source review подтвердил: SOLID/TOPOLOGY сейчас в основном проверяют `abs(volume)`/стек,
а SURFACE/ENCLOSURE/APERTURE переиспользуют deviation/volume без реального измерения
aperture/enclosure. Наличие имён этих семейств **не доказывает их реализацию**.

| Проверка | Обязательная независимая часть |
|---|---|
| Surface/topology | Общие углы и подрёбра, vertex links/face fans, отсутствие T-junction, дублей, zero-area/bow-tie и непредусмотренных границ |
| Solid | Watertight/manifold, edge valence=2 и противоположное использование directed edges, согласованная ориентация, signed volume > 0, компоненты и отсутствие triangle self-intersections |
| Reference/direction/thickness | Расстояния до локальных inner/outer плоскостей, outward каждого сегмента, сохранённый внутренний контур; не fixed global Y |
| Corners | Фактические выпуклые/вогнутые miters против валидного offset, без зазоров, наложений и неконтролируемых длин |
| Apertures | Независимые jamb/sill/head, сквозная пустота через толщину стены, отсутствие неразрешённого host; заполнение отдельно от стенового solid |
| Enclosure/interfaces | Поэтажные сечения, полнота стен по высоте, плиты/крыша и их отметки, отсутствие лишних швов/объёмов между этажами |
| Stack/placement/rebuild | Реальный Editable Poly + один Shell и его параметры; transforms и монтаж экземпляров; три реальные rebuild-популяции |

Полный oracle не может быть простым повторным вызовом builder `prepare()`/`offset()`.
Нужны отдельный расчёт из source-contours, независимые эталоны и проверка экспортированных
чисел/mesh данных достаточной точности. Bbox — только диагностическая/локальная проверка,
замкнутые рёбра и один совпавший объём не заменяют геометрическую валидность.

Прежние coverage, census, NURBS census, analytical curve/form precision, placement, unit guards
и replay/rebuild проверки сохраняются по своему применимому контракту. Cell coverage,
нулевой стек и hidden-host обязательны для legacy, но не универсальны для v2.
Неполный evidence или отсутствие необходимой проверки ⇒ `INCOMPLETE`/`NOT RUN`, не PASS.
Нет подстановки отсутствующей/непарсируемой/nonfinite метрики нулём. Явно поддержать Double
`d`-экспоненты Max и положительный **signed** volume, не только `abs()`.

### Исправления аудита, обязательные для реализации

- Для допустимого простого offset и непересекающихся проёмов вдали от углов:
  `V = (A_outer − A_inner) × H − Σ(w_opening × h_opening × t)`.
  Нельзя заменить площадь кольца одним `P_inner × t`: угловые добавки тоже дают объём.
  Для inner 6×4 м, H=3 м, t=0.3 м: `(6.6×4.6−6×4)×3=19.08 м³`.
  После двери 1×2.1, окна 1.8×1.2 и окна 2×1.3: `19.08−6.86×0.3=17.022 м³`.
- Для outer 12×8 м внутренний прямоугольник при t=0.3 м — 11.4×7.4 м;
  с двумя указанными проёмами измерено 33.57 м³. Формулу нельзя распространять
  на пересекающиеся offsets или угловые проёмы без отдельного вывода.
- `−0.0000305176 мм` в минимуме outer-case — Float32-артефакт, не «точный 0».
  Объём косоугольного case округлён wire до 16.3198 м³; допуски прототипа
  0.01 cm для bbox и 1e−5 relative для объёма не являются общей production-сертификацией.
- `Shell.overrideEdgeMatID`/`matEdgeID` отсутствуют; проверенный side-ID маршрут —
  `overrideMatID`/`matID`. Это исправление API, **не возобновление P7 материалов**.
- Whole-floor Z union и общие corner IDs — условие прототипа. Per-facade Z seams,
  универсальная безопасность outward offset и «frame=opening решает Z-fighting» не доказаны.

ради обхода этой ошибки. Проверить запуск из изолированной установленной копии и отсутствие
нужды читать source-tree sidecars; наличие Python helper в архиве само по себе не готовность.

До cutover `legacy_cells_v1` остаётся явным compatibility-путём; прежний
`poly_surface_shell_v1` не переименовывается в v2 задним числом. Несовпавшая route/schema
ошибочна до записи. Никакого молчаливого fallback, удаления старых проектов или Audit wholesale.
Новый default вводится только по фактически исполненному и измеренному production-коду.

Live Max разрешён уполномоченным агентам: один координируемый live-оператор, без main-only
запрета и без параллельных Max-вызовов. До действий — свежее состояние и владение;
после — raw responses, числа и остатки. Принятый образец автоматически не удалять/перестраивать;
визуальная приёмка не возвращает старый общий запрет на необходимые Max-вызовы.
Обычный лимит ~2 s/script, ≤5 modifiers/call; >10 в стеке требует согласия.
Не повторять fatal stack ladder, `formattedPrint` и synthetic `nurbsID`; не менять units,
не делать reset/save, не очищать dirty/save-required, не удалять по произвольному prefix.

P7/материалы/UV и P9/экспорт остаются отменены. Автор плана не запускает installer.
Координатор отдельно делает **archive-only** пересборку документации `.skill`, без глобальной
установки или смены production-default; эта maintenance-операция не закрывает фазу 5.
Фаза 5 требует actual implementation, изолированной installed-copy проверки, сохранности
пользовательских файлов и отдельного решения о production-выпуске.
