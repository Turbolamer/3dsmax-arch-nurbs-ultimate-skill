## 1. Цель и границы

**Цель.** Дать агенту-моделлеру способ записать форму числами и параметрами, чтобы геометрию определяла формула, а не арифметика в уме. Форму должно быть можно проверить офлайн (валидатор) и в живом Max (замер против формулы).

**Что значит «форма» здесь.** Кривая профиля (дуга, эллипс), кольцо контура в массинге, поверхность над этими кривыми.

**Вне границ. Не делай, не заглушай, не упоминай как «следующий шаг»:**
- материалы, UV, Corona (P7);
- автоматический QA-этап и `qa.json` (P8);
- экспорт (P9);
- назначение слоёв из скрипта (невозможно, девять путей проверено).

Это решение пользователя, оно записано в `SKILL.md` §0.2.

Про модификаторы см. раздел 4.1. Их нет в списке «вне границ»: ограничения там уже и точнее.

## 4. Жёсткие правила

Каждое правило куплено инцидентом. Не ищи обходов.

| Правило | Источник |
|---|---|
| MAXScript, выполненный в Max, единственная истина. Инструменты introspection врут (`introspect_class "NURBSSet"` отвечает «не найден», класс при этом создаётся) | `AGENTS.md` |
| Любое утверждение «класс или свойство существует или нет» идёт с заведомо ложным контролем и заведомо верным контролем в том же вызове. Сравнивай с `undefined`. Не используй `(execute code) as string` для проверки существования | `SKILL.md` §6.5 |
| Отрицательный вывод («нельзя», «не существует») принимается только с транскриптом точной ошибки | `max-nurbs.md` §10.2 |
| Не переписывай справочник по подозрению. Проверь утверждение в Max, правь только то, что не прошло | `AGENTS.md` |
| Один вызов `execute_maxscript` это один скрипт короче ~2 с. Он идёт в главном потоке Max | `SKILL.md` §7.1 |
| Только последовательные записи. Параллельные мутирующие вызовы ломают undo и роняют мост | `SKILL.md` §1.5 |
| Единицы сцены: сантиметры, масштаб 1.0. `points_cm` попадает в Max без пересчёта | `max-nurbs.md` §7 |
| `local` на верхнем уровне `.ms` это ошибка компиляции. Скобочная форма `try { } catch { }` это ошибка разбора. Пиши `try ( ) catch ( )` | `SKILL.md` §7 |

### 4.1 Модификаторы: что именно ограничено

Слово «запрет» в репозитории покрывает три разные вещи. Не смешивай их.

| Что | Откуда | Тип |
|---|---|---|
| Глубина стека. Двадцать модификаторов на одном `Box` за один вызов повесили главный поток Max. Процесс пришлось убить, машину перезагрузить. Пять и десять прошли чисто. Где перелом между 10 и 20, не установлено | `CHECKPOINT.md`, лестница P6 | измеренный предел |
| Нерабочие классы. `Boolean` прикрепляется и молча ничего не режет. `Extrude`, `Sweep`, `Lathe`, `Surface`, `CrossSection`, `Bevel_Profile` не прикрепляются скриптом. Первые пять работают через инструмент `3dsmax-mcp_add_modifier`, `Bevel_Profile` не работает нигде | `CHECKPOINT.md` (P4b-r, P6), `SKILL.md` §1.4 | дефект этой сборки |
| Ноль модификаторов в выходе `assembly.ms` (G-81) | `SKILL.md` §5.2, решение стадии P6 | выбор дизайна. Вытекает из измерения (`Boolean` не режет, проёмы набраны ячейками) и снимает риск зависания по глубине стека конструктивно, без разбиения на куски |

**Правила для тебя.**
1. Модификаторы разрешены. Условия: класс из проверенного набора или своя проба на новый класс с контролем (рабочий класс и заведомо несуществующее имя в том же вызове); не больше 5 за один вызов; на одном узле не больше 10 без вопроса пользователю.
2. Лестницу на 20 модификаторов не повторяй. Ответ стоил перезагрузки.
3. `Boolean` для резки не используй. Он ничего не режет и не сообщает об этом. Другие пути в репозитории не проверялись как способ резки. `ProBoolean` там только сконструирован: это объект (`GeometryClass`), не модификатор, и он оставляет узел в сцене (три сироты за пробу), работа резки не проверялась. Разрез через `Edit_Poly` не пробовался вовсе. Пробуй их только после «да» пользователя, одной пробой с контролем и с очисткой сирот.
4. `Sweep`, `Extrude`, `Lathe`, `Surface`, `CrossSection` ставятся только инструментом `add_modifier`. В эмитируемый `.ms` они попасть не могут. Значит, в цепочку «спецификация, `.ms`, замер» они не встраиваются.
5. Выход `assembly.ms` остаётся без модификаторов (G-81). Менять G-81 можно только вопросом пользователю и по шагам §12.
6. Если результат с модификатором должен остаться в сцене, схлопни его через `collapse_modifier_stack`. Для этих классов схлопывание не проверено, это отдельная проба.
7. Для фаз 0-4 модификаторы не нужны. Для фазы 8 тоже: меш собирается через `polyop`.

## 5. Подготовка и подключение к Max

1. **Репозиторий.** `git status` чистый. Создай ветку `feat/form-generators`. В `main` не коммить. Пуш ветки только после просьбы пользователя.
2. **Python.** `python -m py_compile scripts/*.py` проходит. Это единственный «тест» пакета.
3. **Сцена.** Попроси пользователя открыть новую пустую сцену. Проверь одним вызовом: `objects.count == 0` и `units.SystemType == #centimeters` (читай `units.SystemType` напрямую, `getProperty units #SystemType` не работает). Если сцена не пустая, остановись и спроси. Чужие объекты не удаляй никогда. Работа `nurbs.ms` в непустой сцене не проверена.
4. **Preflight.** Выполни по `SKILL.md` §6.4 шаг 1: `python scripts/env_preflight.py` печатает тела проб, ты вставляешь их в `execute_maxscript`, собираешь ответы в JSON, запускаешь с `--results`. Голый запуск выходит с кодом 0 и всеми SKIP. Он ничего не проверил, считай его отсутствием запуска. Ожидаемый итог: `PASS 9/9`.
5. **Рабочий каталог проекта.** Не работай в `examples/`. Создай временный проект: `python scripts/init_project.py --project rehearsal-form --dir <tmp> --from examples`, затем удали четыре вычисляемых файла (`massing.json`, `facade_grids.json`, `components_registry.json`, `assembly.json`), оставь `nurbs.json`. Причина в `max-orchestrator.md` §4.0 (две ловушки репетиции).
6. **Абсолютный путь.** В Python вычисли `os.path.abspath(...)` для каждого `.ms`, замени `\` на `/`, напечатай и только потом передай в `fileIn`.

## 6. Принятые решения по дизайну

Это отправная точка. Фаза 1 оформляет их в записку. Менять их можно только вопросом пользователю.

| # | Решение | Основание |
|---|---|---|
| D1 | `points_cm` остаётся единственным геометрическим примитивом для построителей. `build_nurbs.py` и эмитируемый `.ms` о генераторах не знают | `07` §8.2 (преамбула): «no new primitive» |
| D2 | Генератор лежит внутри секции: ключ `sections[].generator`. Второй геометрической таблицы нет | `max-nurbs.md` §10.1: вторая таблица это изменение схемы |
| D3 | У секции с генератором `points_cm` это `derived` с `derives_from: ["sections[i].generator"]`. Валидатор пересчитывает точки. Ручная правка даёт FAIL | `07` §12: вычисленное значение без пересчитывающего инварианта запрещено |
| D4 | Версия 1 знает два вида: `arc` и `ellipse_arc`. Плоскости `XY`, `XZ`, `YZ`. Число точек задаётся явным `count` | малый объём, каждый вид нужно проверить в Max |
| D5 | Ключи: `kind`, `plane`, `center_cm` `[x,y,z]`, `radius_cm` (для `arc`), `semi_axes_cm` `[a,b]` (для `ellipse_arc`), `from_deg`, `to_deg`, `count`. Длины с `_cm`, углы с `_deg` | G-8 |
| D6 | Точки идут с равным шагом угла параметра: `P(t) = C + a·cos(t)·e1 + b·sin(t)·e2`. Оба конца точные. Равные шаги по X запрещены: на крутом участке они дают грубую ломаную | F4, F5 |
| D7 | Все секции одной поверхности имеют одинаковый `count`. G-42 уже требует одинаковое число точек | `07` G-42 |
| D8 | **Открытый вопрос.** Откуда берутся параметры формы (подъём 180, радиус 300)? G-49 запрещает им быть `assumed` в `nurbs.json`. Варианты ниже | F8 |
| D9 | Подсказка числа точек по допуску живёт в скрипте (`--suggest-count`), а не в спецификации. В файле всегда явный `count` | иначе валидатору пришлось бы воспроизводить алгоритм подбора |
| D10 | Версия схемы: решить в записке. Предложение: минорный подъём `1.0` на `1.1` для новых файлов. Старые файлы без генератора остаются валидными без правок | `07` §12 |

**Варианты для D8.** Опиши оба в записке и спроси пользователя.

- **Вариант A.** Параметры формы получают место в `dimensions.json` (например, ключи в `roof`) и идут через обычный S1: `given`, `assumed`, `conflict` с записями в реестрах. `nurbs.json` берёт их как `derived`. Плюс: вся цепочка происхождения остаётся единой. Минус: правка схемы `dimensions.json`, которая затрагивает S1.

## 8. Протокол живых проб

Это постоянные правила на каждый вызов `execute_maxscript`.

1. Один вызов, один скрипт, короче ~2 с. Независимые проверки склей в один вызов.
2. Контроли в том же вызове: заведомо верный и заведомо ложный. Сравнивай с `undefined`.
3. Неудачный скрипт возвращает `success: true` и `result`, начинающийся с `__MCP_MS_ERR__:`. Проверяй этот префикс. Одной проверки `success` недостаточно.
4. Числа в строки превращай так: `"text" + (value as string)`. `"text" + число` бросает ошибку типа, похожую на поломку инструмента.
5. `getProperty` берёт Name: `getProperty o ("radius" as name)`. Скобочный доступ `o["name"]` недопустим.
6. Мутаторы NURBS возвращают статус. Читай состояние обратно, возврату не верь.
7. `evalPos` работает только на закоммиченной поверхности. Домен читай из набора. `[0,1]` по привычке брать нельзя: у `point_grid` домен по длине хорды, у `cv_grid` и обоих sweep `[0,1]`.
8. Подобъект находи через `superClassOf`, а не по литеральному индексу. У `point_grid` nU·nV точек стоят **перед** поверхностью.
9. Сравнение с решёткой допустимо только для интерполирующей поверхности. Для `cv_grid` сравнивай с формулой.
10. Харнесс сравнения печатает число выполненных сравнений. Вердикт без ожидаемого числа не считается.
11. Очистка: сначала собери имена в массив, потом удаляй по именам. `for o in objects do delete o` молча пропускает элементы. Делай два прохода. Удаление базы не удаляет экземпляры.
12. Вызов `Corona()` не нужен и не используется.
13. `render_scene` не вызывай без просьбы.
14. Для обзора результата можно `capture_multi_view` или `capture_viewport`, но это не замер. Замер это число.
15. Проба нового класса модификатора: контроль известно рабочий класс (`Chamfer`) и заведомо несуществующее имя. Читай `node.modifiers.count` до и после. Ответ «прикрепился» ничего не говорит о том, что модификатор работает. Измерь результат (число вершин, граней, bbox).
16. Рост нагрузки ступенями. Для проб на размер (число вершин меша) начинай с малого, увеличивай ступенями и останавливайся, когда вызов превышает ~1 с. До зависания Max не доводи.

## Приложение Б. Эталонная реализация точек (проверена при подготовке брифа)

Это опорный расчёт, а не готовый модуль. Реализуй в `scripts/curve_gen.py` по правилам репозитория и сверься с этим кодом.

```python
import math

def q(x):                       # 6 знаков, без отрицательного нуля
    r = round(x, 6)
    return 0.0 if r == 0 else r

def _ab(g):
    if g["kind"] == "arc":
        return g["radius_cm"], g["radius_cm"]
    return g["semi_axes_cm"]

def generator_points(g):
    a, b = _ab(g)
    i0, i1 = {"XY": (0, 1), "XZ": (0, 2), "YZ": (1, 2)}[g["plane"]]
    n = g["count"]
    t0, t1 = math.radians(g["from_deg"]), math.radians(g["to_deg"])
    pts = []
    for i in range(n):
        t = t0 + (t1 - t0) * i / (n - 1)
        p = list(g["center_cm"])
        p[i0] += a * math.cos(t)
        p[i1] += b * math.sin(t)
        pts.append([q(v) for v in p])
    return pts

def max_chord_dev(g, n, dense=200):
    """Верхняя оценка: расстояние от настоящей кривой до ломаной по n точкам."""
    a, b = _ab(g)
    t0, t1 = math.radians(g["from_deg"]), math.radians(g["to_deg"])
    e = lambda t: (a * math.cos(t), b * math.sin(t))
    ts = [t0 + (t1 - t0) * i / (n - 1) for i in range(n)]
    worst = 0.0
    for i in range(n - 1):
        p, r = e(ts[i]), e(ts[i + 1])
        dx, dy = r[0] - p[0], r[1] - p[1]
        l2 = dx * dx + dy * dy
        for k in range(1, dense):
            x, y = e(ts[i] + (ts[i + 1] - ts[i]) * k / dense)
            u = max(0.0, min(1.0, ((x - p[0]) * dx + (y - p[1]) * dy) / l2))
            worst = max(worst, math.hypot(x - p[0] - u * dx, y - p[1] - u * dy))
    return worst
```

Контрольные значения для эллипса `a=600, b=180`, дуга от 180° до 0°, оценка для ломаной:

| точек | макс. отклонение, см |
|---|---|
| 7 | 15.79 |
| 25 | 1.26 |
| 37 | 0.57 |
| 41 | 0.46 |
| 49 | 0.32 |

Для `count = 7` на этом эллипсе `generator_points` даёт середину `[600.0, 0.0, 580.0]` и концы `[0.0, 0.0, 400.0]`, `[1200.0, 0.0, 400.0]`.

Реальная кривая в Max строится через точки (`makePointCurve`) и может быть точнее ломаной. Сколько точнее, покажет фаза 2.
