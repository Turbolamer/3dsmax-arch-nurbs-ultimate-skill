This is an implementation coordination brief, not evidence of a completed builder or a live QA pass. It resolves the bounded P2 integration details identified in `Audit/_phase16-p2-integration-audit.md` for an initial **straight-run declaration**, without inventing building geometry. `Audit/AGENT_PLAN_poly_surface_shell.md` §I remains the record of the user's earlier decisions. ## Route and compatibility

- Select once: `walls.json.wall_technique` is `legacy_cells_v1` or `poly_surface_shell_v1`. A project with **neither walls.json nor an assembly selector** is historical legacy, retaining the same behavior. Unknown/invalid/conflicting/partial selectors and a declared selector without a valid walls document fail closed, never fall back to legacy. Fresh non-seeded scaffold explicitly declares poly with a **draft**, empty walls file; historical `--from examples` remains legacy if the source has no walls selector. No historical example is silently rewritten.
- With an actual poly assembly, `assembly.json.wall_technique` matches walls and `wall_ref` equals `wall_surface.json`; `wall_cells` and `opening_cuts` must be absent, not merely empty. Historical legacy assembly needs neither selector nor walls file; explicitly selected legacy keeps both arrays and existing G-76/77/81/82/83. Draft, empty scaffold assembly is not a produced assembly and stays visibly incomplete. P2 introduces no functional S5 poly build; `place_components.py` must refuse that route before writing.
- Maintain existing source tracing, G-1…G-91 and exact current legacy behavior. P2's JSON lint is **not** runtime acceptance. Avoid enabling poly as a usable build before the builder, route integration, and QA exist.

## `walls.json` v1.1: proposed initial data-only contract

Standard six-key envelope in established order, schema version `1.1`, spec `walls`, `units` cm/deg; `tolerances` exactly the three fields copied from `dimensions.json`; `origin_inputs` and `origins` follow existing path/origin/ledger rules, with every non-exempt domain leaf covered once when locked. Source can be user brief or derived according to existing grammar; do not claim values without a source. `wall_technique` is explicit. `reference_face` is `inner` for this first supported poly subset; `outer` may not be silently treated as inner (it requires its own future verified path). `numeric_epsilon_cm` is a separate positive finite linear epsilon in cm; `numeric_unit_epsilon` is a separate positive finite dimensionless vector/normal epsilon. Neither replaces design tolerance; no numeric value is inferred from the F01 experiment.

- `blocks[]`: `{id, z_range_cm:[base,top]}`; unique IDs, finite ordered bounds.
- `wall_runs[]`: `{id, block_id, contour_ref, start_cm:[x,y], end_cm:[x,y], outward:[nx,ny], thickness_cm, base_z_cm, top_z_cm, topology_budget}`. IDs globally unique across runs and returns, block resolves, finite numbers, positive length/thickness and strict `base < top` within block range. `start/end/z` are project/world cm, not scene units. Initial `contour_ref` is exactly `dimensions.json:facades:<id>`; it must resolve to **one** existing facade, not merely a first match, and the directed run may be a subsegment of its start→end segment within the project's linear tolerance. Since a facade's labelled side does not prove its physical inner/outer face, provenance/reference_face must identify it; do not infer from name/direction. This bounded target is an initial representational limitation; do not claim it covers arbitrary internal upper returns or all architectures.
- `outward` is a finite unit-length XY vector perpendicular to the run direction, evaluated with `numeric_unit_epsilon`; no choice of winding is silently invented for conflicting geometry. Define `t=(end-start)/length` and local `P(u,v)=(start.x+t.x*u,start.y+t.y*u,base_z_cm+v)`. `u` is measured from start and `v` from base; outward is an independent supplied semantic vector. Later builder chooses winding so surface normal matches outward and converts cm to scene units. `direction_deg` is not the run angle.
- `openings[]`: `{id, wall_run_id, kind, u_range_cm:[lo,hi], sill_cm, head_cm}`. Unique IDs, existing run, finite strictly ordered bounds, `0<=lo<hi<=length`, `0<=sill<head<=top-base`; `kind` is `window` or `door`. Different openings on the same run must not overlap in u (plan G-94); no one-opening-per-bay restriction. Door can start at v=0 and is a boundary notch. Values are rough openings, not frame/trim geometry. Optional source provenance belongs to the general origins mechanism, not an unchecked arbitrary reference.
- `upper_returns[]`: use the *same fields and constraints* as `wall_runs[]`, plus `adjacent_run_ids` exactly two distinct IDs resolving to other runs/returns. This declares geometry and contacts; it does not itself prove enclosure or weld correctness. The strict facade source limitation also applies: a return without a valid source must not be invented or accepted as covered. No all-building enclosure PASS without independently validated cross-sections and future QA.
- Every `topology_budget` is a closed object of non-negative integers `{max_grid_polygons, max_base_active_polygons, max_evaluated_triangles}`. These are declared ceilings, not measurements: grid before removals, active base after removals excluding dead elements, evaluated triangle mesh after Shell. Counts of 15/12/96 are *only* F01, never defaults. Do not automatically optimize or claim actual scene counts at lint time.
- A fresh scaffold may use empty arrays, empty provenance and null pending epsilon/reference-face values under `status:draft`; it is never a production-ready wall input. Locked poly requires populated block/run data, complete origins, and all declared parameters. Non-empty draft data is checked as far as possible; `--build` refuses draft per G-4. Do not turn missing evidence into PASS.

## Gate partition and acceptance

- G-92 route/echo agreement; G-93 closed schema, finite values, geometry/ID/contour/provenance joins; G-94 opening intervals and overlaps; G-96 route array exclusivity; G-97 topology budget **declaration** (not measured geometry).
- G-95 (emitted stack), G-98 (manifest and live geometry), G-99 (emitter/live unit guard), G-100 (script safety and real replay) are **SKIP at JSON lint**. Future build/runtime gates own their evidence; missing locked poly output is visibly incomplete / a build-gate refusal at the appropriate *output* boundary, not a permanent precondition that prevents the future builder from consuming locked inputs.
- All route-inapplicable legacy G-76/77/81/82/83 are reported SKIP in poly, not removed or relaxed for legacy. Invalid selector is a FAIL, not a valid poly branch. Common assembly checks stay enabled where inputs exist.
- Acceptance needs legacy examples, stepped-tower and form-precision baseline unchanged; negative injection for selectors, schema/IDs, non-finite values, contour resolution/disagreement, outward vectors, openings, provenance, tolerance/epsilon, budget, and legacy/poly assembly mixing. No live pass is declared in P2.

This narrow P2 contract is not a user requirement to discard outer-reference walls, unrepresented contours or returns: those cases must remain honestly unsupported/incomplete until their own contract and verification are implemented. Layer-application policy stays deferred.
