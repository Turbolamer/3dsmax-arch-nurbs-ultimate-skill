## Blocking findings and bounded repairs

1. **Independent witness continuity — source-proven protocol gap, not an observed substituted-lease exploit.** The wall reads `registryWitness = globalVars.get registryKey`, and the late `globalVars.get == registryWitness` check merely compares against the object read by that same invocation (`scripts/wall_surface_runtime.py:722-734,816-825`; Main03 `.ms:276-288,370-379`). The held-file wrapper authenticates file bytes, not the external lease (`Audit/phase16-p3-main-build-2026-11-02e/Main03/held_pair_filein.ms:41-70`). The Main03 attempt's independent `local witness` was checked while that one outer script was running (`Audit/_phase16-p3-main03-live-attempt-2026-11-02e.ms:4-15,18-27`); the retained transcript does not demonstrate the same local surviving across later bridge calls. A fresh equal-looking struct can satisfy the wall's shape/nonce checks unless the separate witness is compared; nonce length is not identity or authentication. Even the same struct can contain a changed `.values` array: source checks the nonce's length but not equality to a separately retained expected nonce (`scripts/wall_surface_runtime.py:729-734`). The narrow registry probe did distinguish alias from separate structs **within one harness** (`Audit/_phase16-p3-registry-probe-2026-11-02e.json:3-10`), not across the actual multi-call lifecycle.
   * Repair the main-owned protocol: retain the *original exact struct* independently of its registry (one uninterrupted owning harness, or a separately calibrated persistent witness channel with explicit lifecycle); check it against the global immediately before **every** arm-following wall fileIn, including replays, plus appropriate after-state checks. Independently retain detached expected nonce, immutable identity/context and authorized state-transition evidence; pointer equality alone cannot detect changes within the same struct. Never reacquire the witness from the registry and call that independent. Treat lost witness, reset/open/new/merge/restart, ambiguous callback, timeout or unexpected state as INCOMPLETE; never adopt/rearm. Under the stated trusted sequential single-writer model this is an operational boundary, not a defense against malicious scripts (`Audit/_phase16-p3-runtime-design-2026-11-02e.md:37-53,79-83,103-120`). Run same-instance positive, same-payload new-struct, missing/wrong-global, registry/values replacement, valid-length wrong nonce/identity and broken-witness controls; prove each refusal precedes mutation and preserves the original witness and scene. If persistence cannot be proved, leave replay unsupported.

2. **BUILDING/COMMITTED and interruption — source-proven state-machine gaps.** `lease[5] = "BUILDING"` precedes the local `attemptStarted` flag; interruption/throw between them can leave a BUILDING lease. Creation references/handles are only in local arrays until the catch, so a timeout, process crash or interrupted `fileIn` need not execute cleanup or persist ownership (`scripts/wall_surface_runtime.py:757-774,829-859`). The code accepts ARM based on shape/identity but does not compare the arm's `lease[10]` save-required observation before starting (`:722-759`), so an intervening dirty-flag change is not rejected by that check. After two *bounded* reads it sets COMMITTED while explicitly logging replay metadata incomplete (`:816-826`); the design says no COMMITTED state if full baseline is incomplete (`Audit/_phase16-p3-runtime-design-2026-11-02e.md:200-221`). No false NOOP is currently emitted (`scripts/wall_surface_runtime.py:735-749`), but treating COMMITTED or `P3_CREATED_UNVERIFIED` as acceptance would be wrong.
   * Separate construction-only provisional state from fully validated replay COMMITTED, or obtain an explicit contract decision before changing semantics. Preserve the unconditional `INCOMPLETE_REPLAY` barrier until completeness is demonstrated. Persist each attempt reference/handle immediately into the independently witnessed lease before the next risky operation where the APIs permit; if construction succeeds but recording is interrupted, classify as unresolved, not clean. Record/check approved environment including dirty state before BUILDING, without clearing/restoring it. Define recovery of every interruption as inspect-only, no retry or inferred rollback. Offline fault injection should cover before/after BUILDING, constructor, reference/handle capture, conversion, every publication field and final transition; main-only bounded controls must verify actual state, exact census and refusal on a stale BUILDING lease.

3. **Conversion and cleanup — source-proven unsafe branches; actual harmful deletion remains unproven.** `convertTo` can return a node that fails the original handle check *before* `createdRefs[1]` is updated (`scripts/wall_surface_runtime.py:766-774`). If conversion invalidates the original and the returned node or handle cannot be proved continuous, catch can lack a recorded valid exact ref: an unknown conversion residue can be reported only via census. Conversely catch falls back from an invalid reference to `getAnimByHandle` and may delete the returned node based on handle, one-node census, hierarchy and base sharing, without proving it is the same original exact live reference (`:834-850`). Whether handle reuse or the unrecorded-conversion case occurs here is **unverified**, not a demonstrated incident. Cleanup also does not screen foreign non-node dependents of the node/base/modifier despite the design's requirement (`:841-848`; `Audit/_phase16-p3-runtime-design-2026-11-02e.md:230-252`).
   * Record the returned conversion candidate before any validation that may throw, without promoting it to owned deletion authority until a calibrated exact-reference/handle continuity proof succeeds. Never delete a handle-reacquired object solely because a number, name/tag, class or census matches; if identity is ambiguous, retain/report all candidate handles and refs, exact observed census, reason, and INCOMPLETE. Add a bounded calibrated dependency/attachment exclusion for known-safe cleanup; unknown or unreadable external dependency means no deletion. A baseline invalidation or unit mismatch must not be "fixed" to enable cleanup. Re-read original node and complete census after deletion, checking the exact survivor set rather than count alone. Controlled fault cases: constructor before handle, conversion return/old-ref invalidation/wrong-handle, deleted/reused-or-unresolvable handle simulation, foreign parent/child, base instance, non-node dependent, unit drift, delete/readback throw and residual; compare exact untouched neighbor identities and report all uncertainty. Do not simulate by destroying user scene data.

4. **Cleanup can mislabel unknown outcome — source-proven.** Cleanup guard exceptions are swallowed (`scripts/wall_surface_runtime.py:839-850`); if the created ref is already invalid, an unresolved handle lookup plus `objects.count == 0` yields no residual entry (`:836-853`), so `P3_REFUSED` is possible without a proof that no unknown node was deleted or that ownership disappeared. The post-failure census check is conditional on `createdRefs.count > 0` (`:853`): if a constructor were to make a scene object and throw before returning/recording it, the code would miss even a nonzero census; such partial constructor behavior is **speculative**, not established by Max evidence. `evaluatedSnapshot` separately prints `P3_INCOMPLETE|...disposal failed` and rethrows (`:647-674`), while the outer status selects only the residual array (`:860-862`); an operator looking only at the final marker could misclassify it. The arm failure handler also swallows failure to remove its just-declared global (`:426-440`).
   * Track success, no-attempt, unknown identity, cleanup-guard failure, deletion-verification failure and mesh-disposal failure as separate structured outcomes; any unknown/failed cleanup is INCOMPLETE even if census is zero. Preserve the original error and all cleanup exceptions. Verify removal of an exact newly declared arm global; if verification fails, report its key and INCOMPLETE, never remove a pre-existing key. Main must parse raw bridge error, all diagnostic markers and wrapper close/disposal outcomes, not `ok=true` or final status alone (`Audit/_phase16-p3-contract-2026-11-02e.md:44`). Add controlled exception-injection tests for each path plus healthy delete/dispose positives; do not claim crash atomicity.

The later default-layer probe found self/default equality and stable typed values, but handle/ref-count still throw and distinct-layer identity/edit discrimination are absent (`scripts/wall_surface_runtime.py:492-535,684-699`; `Audit/phase16-p3-state-probes-2026-11-02e/layer-comparison-evidence.txt:2-19`; `Audit/_phase16-p3-post-test-layer-and-scene-2026-11-02e.json:3-10`).    * Calibrate a bounded layer-specific identity and detached typed-state reader with same-layer positive, distinct-layer negative and owned layer-state mutation controls, or refuse; do not substitute name/scalars for proven identity. Classify each required property as readable, specifically proven inapplicable, or unsupported; no generic absent-equals-absent for required state. Copy the user buffer and test alias independence. For specified normals and every supported native/custom data class, prove exhaustive detached comparisons or prove absence *and detection of addition*. Keep INCOMPLETE when a category is unobservable; run same-count/same-coordinate metadata edits as discriminating negatives. A single safe layer probe does not establish the full list.

6. **Evaluation occurs before controller/dependency safety — source-proven ordering; hazard not live demonstrated.** `nodeSnapshot` calls `polySnapshot`, then `evaluatedSnapshot` (`snapshotAsMesh`), and only then `graphSnapshot` (`scripts/wall_surface_runtime.py:647-661,676-699`); Shell's early checks cover three numeric properties, not all editable parameters (`:681-683`). The graph accepts `numKeys == -1` and captures dependents but does not prove every descendant is static or classify the initially permitted dependency graph (`:559-594`). Main's static-PRS `-1` observation is a positive for one controller, not proof for all descendants (`Audit/_phase16-p3-runtime-2026-11-02e.md:149-156`).
   * Before any evaluated geometry, check exact node/base/modifier identities, census, type/counts, enabled states, calibrated complete supported Shell settings, controller descendants/classes/custom attributes and permitted bounded dependencies; unknowns refuse. Compare detached supported parameters before evaluating. Bound count/depth and observe runtime, not just final triangle count (the latter is checked *after* snapshot creation). Test static-composite positive against keyed child, wired/scripted/unknown controller, additional/replaced modifier, excessive Shell subdivision and foreign dependent; prove refusal without calling the evaluated snapshot. Keep arbitrary plugin/state support outside scope.
