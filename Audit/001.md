### 1. Патч для `references/08-input-rules.md` (Вставить после §1.2)

Этот блок вводит формальный протокол деконструкции визуальных референсов (**Visual & Proportional Deconstruction Protocol**), связывая визуальные пропорции с массивом `raw_source_values[]` из Schema 1.1 и инвариантами `G-24`…`G-28`.

```markdown
### 1.3 Visual & Proportional Deconstruction Protocol (Image, Render & Sketch References)

When the input includes an image, render, photograph or architectural sketch (`source.kind: "image"`), jumping directly from pixels to centimetre values in `dimensions.json` is forbidden. Visual inputs must pass through a deterministic **4-step proportional deconstruction** before Step 2 unit normalisation:

#### Step 1.3.1 — Perspective & Horizon Guard
Classify the visual source before taking any ratio:
- **`orthographic_elevation`**: direct 2D pixel/ruler ratios along both X and Y axes are valid.
- **`two_point_perspective`** (verticals parallel, horizontals converging): **vertical ratios along the same vertical line are valid**; horizontal bay widths foreshorten toward the vanishing points and must **never** be measured as raw pixel widths. Extract horizontal structure by counting rhythmic modules (`bay_count`) and equal-division symmetry, not by measuring foreshortened pixels.
- **`three_point_perspective` / `aerial`**: both vertical and horizontal ratios foreshorten. Rely on module counting, structural grid alignment, and local ratios within a single coplanar bay.

#### Step 1.3.2 — Scale Anchor Binding (`L_anchor`)
Every image deconstruction requires at least one explicit **Scale Anchor** ($L_{\text{anchor}}$) before any dimension is computed. Rank of anchor preference:
1. **Stated project dimension** in a companion brief or title block (e.g. total span `12000 mm` = `1200.0 cm`, footprint width `1800.0 cm`, or ground-to-first height `420.0 cm`) — yields `confidence: "high"` or `"medium"`.
2. **Standard ergonomic / tectonic reference** visible in the image when the brief is completely silent on scale:
   - Single leaf entrance/service door height: `210.0 cm` (or `220.0 cm` commercial); width: `90.0 cm`–`100.0 cm`.
   - Guardrail / balustrade / roof parapet height: `105.0 cm`–`110.0 cm`.
   - Standard stair riser: `15.0 cm`–`16.5 cm`.
   - Standing human figure scale: `175.0 cm`.
   - Yields `confidence: "low"` and requires an explicit `A-nnn` anchor entry in `assumptions.json`.

#### Step 1.3.3 — Proportional Ratio Chain (Dimensionless Extraction)
Before authoring `_cm` leaves, extract the building's tectonic proportions relative to the local bay or storey module. Record raw ratios or primary scaled measurements in `raw_source_values[]` (Schema 1.1) with `source_reference` pointing to `image:<file>#<region>`:

| Tectonic feature | Ratio definition | Invariant it protects |
|---|---|---|
| **Bay aspect ratio** | $R_{\text{bay}} = W_{\text{bay}} / H_{\text{level}}$ | Locks `structure.x_bay_cm` and `facades[].bay_width_cm` so `Σ bay_width_cm == length_cm` (**G-24**, **G-25**) |
| **Opening-to-bay width ratio** | $R_{\text{op,w}} = W_{\text{opening}} / W_{\text{bay}} \in (0.0, 1.0)$ | Guarantees strict inequality `width_cm < bay_width_cm` (**G-27**) and preserves solid pier widths for S5 `WAL_` cell tiling |
| **Vertical bay partition** | $R_{\text{sill}} + R_{\text{window}} + R_{\text{spandrel}} = 1.0$ | Guarantees `head_cm <= levels[level].height_cm` and `head_cm - sill_cm > 0` (**G-26**) |
| **Arch / vault rise-to-span ratio** | $R_{\text{vault}} = b / (2a) = \text{rise} / \text{span}$ | Derives semi-minor axis $b = R_{\text{vault}} \cdot (2a)$ from semi-major axis $a = \text{span}/2$ in `form_references[]` (**G-86**) |
| **Relief & tectonic depth** | Classified as `flush` (`0 cm`), `recessed_opening` (`15–30 cm` reveal), or `projecting_frame` | Prevents flat facade assumptions and informs S4b `components_registry.json` parameters (`frame_depth_cm`, `glass_offset_cm`) |

#### Step 1.3.4 — Tectonic Rhythm & Symmetry Grammar
Write the elevation's bay rhythm as an explicit pattern before expanding `openings[]`:
- Identify symmetry (`[A, B, B, A]`), repeating bays (`[A, A, A, B]`, as in `pavilion-01` where bay 4 is the full-height glazed stair bay), or blank structural core bays (`[Blank_Core, A]`, as in `pavilion-01` east elevation `A-016`).
- Verify that every opening's pier remainder `(bay_width_cm - width_cm) / 2` is $\ge 10.0\text{ cm}$ so S5 `place_components.py` does not emit degenerate sliver `WAL_` wall cells.

```

### 2. Патч для `agents/max-input.md` (Вставить в §4 Step 3 и §6.2 / §6.4)

Этот патч добавляет правило **Propose-with-Measured-Estimate**: агент больше не блокирует работу пустыми вопросами «какой радиус у свода на картинке?», а сам снимает пропорцию с референса, вычисляет точное значение в сантиметрах, заносит его в `draft`-спецификацию с полной трассировкой и выносит пользователю уже готовое число на подтверждение.

```markdown
### 4.2 Visual reference intake rule (addendum to Step 3 & Step 5)

When an image or sketch is provided alongside or instead of a text brief:
1. **Execute `08` §1.3 first.** Identify the perspective class, bind the Scale Anchor ($L_{\text{anchor}}$), and compute dimensionless ratios ($R_{\text{bay}}$, $R_{\text{op,w}}$, $R_{\text{vault}}$) before writing any `_cm` leaf.
2. **Never ask the user to measure their own image.** If an escalatable topic (such as `form_references[]` radii/semi-axes under D8=A, storey heights, or facade composition) is visible in the provided image, you **must** measure the proportion from the image, compute the candidate `_cm` value against the scale anchor, populate the spec at `status: "draft"` with an `A-nnn` entry (`confidence: "medium"` or `"low"`), and present the **computed candidate value** in your escalation line (§6.4).
3. **Pier sanity for S5 tiling:** When scaling openings from an image, quantise `width_cm` to clean architectural increments (`5.0` or `10.0 cm`) strictly inside `bay_width_cm` (**G-27**) leaving at least `10.0 cm` per side pier so S5 solid-cell wall tiling (`WAL_`) never generates micro-slivers.
```

### 3. Проверочные MAXScript-пробники для снятия ограничений `SKILL.md` (§5.1 и §5.3)

В `SKILL.md` сейчас записано, что:

1. Назначить слой объекту из скрипта невозможно (`node.layer` is read-only, `manage_layers` не умеет).
2. Назначить материалы через прототипы `PROTO_` нельзя, поэтому пользователю нужно красить 136 `PLC_` панелей вручную.

Ниже — два однострочных батча для `3dsmax-mcp_execute_maxscript`, составленных строго по вашему правилу **`SKILL.md` §6.5 (The control rule)** и правилам экранирования **`SKILL.md` §7.1** (без `\n` в строках, скобочный `try (...) catch (...)`, позитивный контроль `1+1` и заведомо несуществующий `TotalGarbageXYZ_fn(1)`).

#### Пробник А: Назначение слоя через `ILayerProperties.addNode` (в обход read-only `node.layer`)

В 3ds Max свойство `node.layer` действительно только для чтения, но сам объект слоя (`LayerManager.getLayerFromName`) имеет метод `.addNode <node>`. Запустите этот пробник в живом Max:

```maxscript
(
    local out = #()
    for code in #("1+1", "TotalGarbageXYZ_fn(1)") do (
        local v = undefined; local threw = false
        try ( v = execute code ) catch ( threw = true )
        append out (code + " => threw=" + (threw as string) + " undef=" + ((v == undefined) as string))
    )
    local b = Box name:"__probe_layer_box" width:10 length:10 height:10
    local lyr = LayerManager.getLayerFromName "__probe_L_WALL"
    if lyr == undefined do lyr = LayerManager.newLayerFromName "__probe_L_WALL"
    local addThrew = false
    try ( lyr.addNode b ) catch ( addThrew = true )
    local assignedName = b.layer.name
    delete $'__probe_layer_box'
    LayerManager.deleteLayerByName "__probe_L_WALL"
    append out ("lyr.addNode => threw=" + (addThrew as string) + " layer=" + assignedName)
    out as string
)

```

* **Что это даст:** Когда вернется `lyr.addNode => threw=false layer=__probe_L_WALL`, вы сможете добавить `lyr.addNode` прямо в генератор `place_components.py` (`assembly.ms`) и `build_spec.py` (`massing.ms`). Все 254 объекта будут автоматически раскладываться по слоям `01_Massing`, `03_Walls`, `04_Facades` и т.д. из `assembly.json.layer_map`, и инвариант «0 nodes off layer 0» превратится в полноценную автоматическую проверку слоев в `qa_check.py`!

#### Пробник Б: Автоматическая раздача материалов с 29 `PROTO_` на все 136 `PLC_` инстансов по `baseObject`

Поскольку каждый `PLC_` делит `baseObject` со своим `PROTO_`, вам не нужно заставлять пользователя красить 136 панелей вручную. Достаточно проверить этот механизм и положить 5-строчный хелпер в `snippets/sync_proto_materials.ms`:

```maxscript
(
    local p = Box name:"PROTO_probe_01" width:100 length:10 height:200
    local inst = copy p
    inst.name = "PLC_probe_01"
    inst.baseObject = p.baseObject
    local m = Standard name:"__probe_mat"
    p.material = m
    local beforeSync = (inst.material != undefined)
    for proto in objects where matchPattern proto.name pattern:"PROTO_*" and proto.material != undefined do (
        for o in objects where o != proto and o.baseObject == proto.baseObject do o.material = proto.material
    )
    local afterSync = (inst.material == p.material)
    delete $'PLC_probe_01'
    delete $'PROTO_probe_01'
    "beforeSync=" + (beforeSync as string) + " afterSync=" + (afterSync as string)
)

```

* **Что это даст для `SKILL.md` §5.1 (Hand-off):** Пользователь назначает Corona-материалы (`_CoronaPhysicalMtl`) **только на 29 прототипов `PROTO_**` в Material Editor, после чего выполняется один вызов синхронизации по `baseObject` — и все 136 `PLC_` получают свои материалы за 5 миллисекунд без единого модификатора в стеке (`G-81` остается `0 modifiers`).
